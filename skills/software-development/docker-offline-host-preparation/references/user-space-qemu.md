# Disposable user-space QEMU rehearsal

Use only with explicit disposable guest authority; never reboot a shared host or infer production readiness from guest results.

- Stage QEMU via a new mode-0700 task directory: isolated APT sources/lists/cache, fresh signed indexes verified by the system Debian archive keyring, simulated dependencies, exact-version `apt-get download`, and `dpkg-deb -x`. Do not run maintainer scripts or alter the host package database. Use process-local LD_LIBRARY_PATH; keep package pins/hashes and APT logs.
- Read the official Debian cloud-image verification policy. Current cloud images publish SHA512SUMS over official HTTPS, not detached signatures. Pin the dated image path and hash; describe TLS/checksum trust honestly rather than claiming GPG image verification.
- Prefer no guest networking at all: resolve guest package dependencies against its extracted dpkg status with the isolated signed APT indexes, then carry public packages on a read-only disk image. Mount it only inside the disposable guest; never mount guest disks on the host or attach host Docker/private sockets.
- Bound QEMU with a task-specific transient user unit (CPUQuota, MemoryMax, MemorySwapMax, TasksMax, RuntimeMaxSec), no NIC, Unix-only control sockets, no-new-privileges and QEMU seccomp sandbox. Read actual cgroup controls. A disk-image size and per-file RLIMIT are not an aggregate filesystem quota; keep expected total below the authorized bound and measure usage.
- Check user lingering before disconnecting. Without linger, logout can stop the user manager and its QEMU unit. Keep a bounded SSH session alive instead of changing global login policy; terminate its exact remote timeout/sleep children and local runner during closure.
- A headless no-VGA GRUB boot may stall before Linux. Extract kernel/initrd from the verified image without host mounts and use direct-kernel boot. Preserve failed logs. A nocloud image may invoke systemd-firstboot and serial login rather than provide an automatic serial shell. For an explicitly disposable guest, bypass firstboot and initialize a serial autologin drop-in via a temporary init shell; remove the init-shell argument before ordinary boot/reboot tests. Never apply these conveniences to a real server.
- Serial sockets are streams: wait for a complete result marker including exit digits and newline; closing immediately after send can truncate input. Avoid terminal line limits by chunking base64 and checksum the reconstructed payload. Do not accept an old prompt from a previous boot; require the new boot marker and wait for Docker readiness separately from the login prompt.
- Exercise the existing PreparationSite port with real guest Docker/systemd/Compose. Preserve originals, commit the durable fence before stopping, prove cold-start and guest-reboot non-recreation, and retain synthetic processed/cancelled/uncertain records. Keep preflight false when the guest-only adapter lacks full authority.
- Before a recovery rehearsal, compare a real generated container inspection with HostOperations' admission validator. Its shared archive validator can reject engine-default security fields (for example Docker26 MaskedPaths lacks /proc/interrupts expected by a newer fixed list) before any fence receipt exists. Preserve the exact rejected inspection and test that no effect occurred; do not rewrite inspection/security settings or relax archive restoration gates just to reach recovery. Review in-place original-container recovery separately from cross-engine archive reproducibility, and report unexecuted crash/current-policy cases explicitly.
- When an in-place/portable validation split is authorized, admit only the observed alternate mask list, keep every unrelated gate, and preserve the unmodified inspection plus exact HostConfig binding. Run RED→GREEN and strict checks before guest execution; separately prove that cold archive capture still refuses the same list. Execute normal recovery and real SIGKILL on both sides of durable start intent in new exclusive guest directories, with current policy revision changes, no replay and a never-started target. Export and hash-read back the exact executed modules, old generated state, recovery receipts and cleanup state; retained earlier failures must not be overwritten. Close parent-owned child log streams explicitly in the manual harness to avoid ResourceWarning noise obscuring crash evidence.
- A local wrapper's expiry/revoke check is not Docker-daemon effect-time enforcement. Separate deliberate trusted-admin bypass (outside a coordinated maintenance trust boundary) from automatic/orphan/accepted requests (inside it); do not invent a universal root-proof gate. Prefer a finite closed requester set, durable operation intent, serialized original RPC terminal response, then persistent fence/stop/readback. Missing receipts, unknown actors or client death stay uncertain and block a second owner; an unrelated inspect/stop is not a queue barrier. This alternative does not itself satisfy an existing effect-time-expiry contract or authorize changing readiness flags. Docker restart explicitly survives client cancellation in relevant upstream versions: verify source for the tested version and reproduce with a daemon signal event, actual requester SIGKILL, old StartedAt still observed after expiry, then new StartedAt. Keep guest-only proof distinct from production actor coverage and clock/suspend guarantees.
- For an agreed scp rehearsal, check the actual production source's strict runtime and writable-layer admission read-only before spending work on a guest-engine incompatibility. A Docker26 fixture's mask refusal need not affect the real source. Keep the gate unchanged; carry app/data, exact image/configuration and current policy in a metadata-preserving representation, compare byte/type/UID/GID/mode/mtime/link topology/ACL/xattr manifests and SQLite integrity before target start, and retain the original. Keep host control locks/anchors outside the portable app/data manifest rather than copying their authority into the target.
- On a no-NIC Q35 guest without a hotplug-capable PCI bridge, use guest poweroff and a task-owned cold-attached transport disk instead of reconfiguring the shared host or repeatedly attempting device_add. Perform real pinned scp on the detached synthetic transport, hash source/controller/destination, then attach the received disk read-only. This proves transport and guest staging, not independent production custody or clean-image-store/cross-engine recovery. Include required mount parents and scratch directories in generated rootfs fixtures so Docker-created parent paths and missing /tmp do not obscure the actual validator checks.
- If the existing recovery primitive requires no target activity, test its truthful refusal after an actual target start; do not set its no-activity flag true. A separately authorized manual synthetic return may retain target delta, reconcile current policy, positively fence the closed requester set and start the retained original with actual terminal receipts. Report that as a manual rehearsal and leave production target-activity recovery explicitly unimplemented, not as Controller RECOVERED.
- Before loading a large pinned application image, measure guest filesystem free space separately from qcow2 virtual size, host free space and compressed registry/Engine image size. Resolve the public index to the exact platform manifest/config and hash-check those small objects without production credentials. HTTP Range reads of gzip footers can estimate uncompressed layer-tar bytes with only eight body bytes per layer; require 206/Content-Range and treat ISIZE as modulo 2^32 metadata, not full-blob integrity or exact installed filesystem size. Budget archive-import scratch plus overlay extraction and retained transport copies; an ample host disk does not enlarge the guest partition. Stop before full pull when the retained limits cannot support this path; do not silently resize, switch stores, delete prior images or substitute a shell/model fixture. Record startup/load as not executed, not passed or as invented exit codes.
- Finish with guest poweroff, QEMU PID absence, no surviving task processes, exact-readback host boot/service PID/start-time/listener/package-database comparisons, retained-artifact sizes, and checksum-verified export. Leave the public-only disk stopped for a separately scoped next stage; do not claim source protection, independent custody, or a migration.
